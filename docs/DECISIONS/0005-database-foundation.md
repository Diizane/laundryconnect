# ADR 0005: Database foundation choices

- Status: accepted
- Date: 2026-07-23

## Context

Milestone 4 introduces PostgreSQL, SQLAlchemy (async), Alembic, the initial
schema (Provider, Manufacturer, Brand, MachineModel, Document, ModelDocument),
and a repository layer.

## Decisions

1. **Async SQLAlchemy 2.0 + asyncpg** for production, matching the async
   FastAPI stack.
2. **SQLite (aiosqlite) for automated tests.** No Docker/PostgreSQL is
   available in every dev environment, and tests must run everywhere fast.
   Portable column types only (sa.Uuid, sa.DateTime, sa.String). Trade-off
   accepted: PostgreSQL-specific behaviour (e.g. tsvector search in M7,
   concurrent constraint semantics) is NOT covered by unit tests. When
   PG-specific features arrive, a separate opt-in PostgreSQL test job joins CI.
3. **The app still starts without a database.** `DATABASE_URL` remains
   optional; the engine is created only when configured, session-dependent
   routes 503 with "Database is not configured", and the readiness endpoint
   runs a real `SELECT 1` (with timeout) when configured, reports `skipped`
   when not, and returns HTTP 503 when the check fails.
4. **Repositories never commit.** They flush; the transaction boundary
   belongs to the request-scoped session dependency (commit on success,
   rollback on exception) or the test.
5. **Alembic from day one, migration verified by tests.** The initial
   migration was autogenerated, reviewed, and is exercised in CI: upgrade →
   full schema, downgrade → clean, and a guard test asserts the migration
   chain and `Base.metadata` describe the same tables.
6. **Constraint naming convention** on `MetaData` so autogenerated
   migrations produce deterministic, portable constraint names.
7. **Readiness/connection failure details expose exception class names
   only** — DSNs and driver messages can embed credentials.

## Consequences

- M6 (machine workspace) builds routes on `DbSessionDep` + repositories with
  no wiring changes.
- M7 document search will add PostgreSQL-specific indexing; that is the
  trigger to add a PostgreSQL service job to CI.
- Timestamps are application-generated (`datetime.now(UTC)`), keeping SQLite
  and PostgreSQL behaviour identical; if DB-server time becomes important,
  revisit with `server_default=func.now()` in a migration.

## Amendment (2026-07-23, Docker verification)

Timestamp columns are now `DateTime(timezone=True)` (migration
`4a1f0b2c9d3e`). The original naive columns worked on SQLite but PostgreSQL
(asyncpg) rejects aware UTC datetimes for naive `timestamp` columns — caught
the first time the stack ran against real PostgreSQL in Docker. This is
exactly the class of dialect gap the "SQLite for tests" trade-off predicted;
container verification is now part of the release checklist.
